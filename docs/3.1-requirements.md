# 3.1 features and validation

Each side shows total moves, blunders, mistakes and verified good-move examples. Accuracy-style totals, phase scores, per-move ratings and rating tooltips are removed so averages cannot conceal key mistakes.

- Blunders and mistakes are separate categories. Good moves count verified positive actual lessons once per real color and ply. Zero means no examples are included.
- Keep the clickable evaluation chart and position-linked advantage bar. Evaluations remain White-oriented when the board flips. They are not accuracy or actual winning probability.
- Keep both sides' lessons, practice, engine continuations, check and checkmate markers, opening recognition and study links.
- Without matching analysis, complete counts and the chart are unavailable. Unanalyzed practice or suggested positions show “Not analyzed”.
- Preserve standalone offline HTML/PGN, per-game note keys, the archive and opted-in incremental common-leaks analysis.

## Validation

Run `python -m unittest discover -s tests` for evaluation orientation, counts, removed rating fields, terminal positions, input matching, import and cross-game rules. Follow the runtime workflow to run `check_insights.cjs` against White, Black and no-analysis examples of the public Opera Game. Check chart navigation, both sides' counts, continuations, unknown evaluations, offline behavior and 390 / 320 pixel layouts. Use `check_review.cjs` for practice, notes and PGN downloads.

README screenshots use public historical and fictional teaching games only. Plugin publication does not change the local-only default for users' reviews. See [analytics definitions](../plugins/chess-review-en/skills/chess-review-open-en/references/analytics.md).
